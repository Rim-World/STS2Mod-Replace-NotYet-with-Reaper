## 4. 施工步骤

### S1 代码修改

文件：`9.SRC/ReaperReplacementMod/PortraitTextureLoader.cs`。

改动点：

1. `Get()` 先判断 `_texture != null && GodotObject.IsInstanceValid(_texture)`，有效则直接返回。
2. 失效时重新加载，加载调用传 `ResourceLoader.CacheMode.Ignore`。
3. pck 加载失败时继续使用现有内嵌 PNG 兜底；内嵌纹理可以静态缓存。
4. 保持 `Log.Warn`、`Log.Error` 的现有提示文本，便于日志检索。
5. 不改 `Patches/` 下的任何文件。

验收：`dotnet build` 0 错误 0 警告；代码评审确认没有新增 `sts2` 依赖。

### S2 构建与导出

执行 `9.SRC/ReaperReplacementMod/build.ps1`，依次完成：

1. `dotnet build -c Debug`。
2. Godot `--headless --import`。
3. Godot `--headless --export-pack "Windows Desktop"`。
4. 拷贝 `ReaperReplacementMod.dll`、`.pdb`、`.json`、`.pck` 到 `mods/ReaperReplacementMod/`。

构建前先改清单版本号，不要只改产物文件名。构建后用版本号检查确认清单、产物目录与发布包一致。

### S3 静态验证

1. 用 Mono.Cecil 扫描新 DLL 对 `refs107`、`refs111`、`refs113` 的成员引用，预期 `unresolvedRefs=0`。
2. 检查 10 个补丁目标，预期 `missingTargets=0`。
3. 用 `strings` 检查新 pck 的 `localization/` 目录，预期仍为 15 个，不出现 `ind`、`ara`。
4. 检查清单：`version` 为合法 SemVer；`min_game_version` 保持 `0.107.1`；`dependencies` 仍为空数组。
5. 检查新 DLL 的 `sts2` 引用版本仍为 `0.1.0.0`。

预期结果：五项全部通过后再进入实机阶段。

## 6. 风险与回滚

| 风险 | 影响 | 措施 |
|---|---|---|
| 切换游戏版本导致 run 存档被判为未来版本 | 存档被改名 `.FUT.corrupt` | 切换前打完或放弃当前 run；备份 `modded/profile*/saves` |
| `CacheMode.Ignore` 使检视卡期间多一份纹理 | 显存占用增加约 3 MB | 可接受；检视界面关闭后随节点释放 |
| `GodotObject.IsInstanceValid` 在当前 Godot 版本行为不同 | 修复失效 | 已核对 GodotSharp 4.5.1 的实现：只读 `NativePtr`，不抛异常 |
| 新 DLL 在旧版本出现成员缺失 | 卡牌无法打出 | S3 三版扫描为门禁；不通过不进入实机 |
| Workshop 与本地副本不一致 | 玩家版本混淆 | 发布后比对两份文件的哈希与清单 |
| 修复无效或引入新问题 | 体验退化 | 回滚到 `10.OUTPUT/01-构建产物` 中 2026-08-29 的 DLL 与 pck |

4. 三版静态扫描均为 `missingTargets=0`、`unresolvedRefs=0`。

6. pck 语言目录为 15 个，不含 `ind`、`ara`。
7. 文档、版本号、产物、发布物一致。
