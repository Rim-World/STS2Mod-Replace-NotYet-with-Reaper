## 版本 0.2.1（2026-08-08）

- **版本号**：0.2.1（当时清单版本号；该版本清单原件未保留，见「失败经验或实验教训」）
- **时间戳**：2026-08-08（ADR-001「2026-08-08 跨版本修复（v0.2.1）」条目；具体时刻未记录）
- **开发人员反馈**：
  - 现象：107 下打出「死亡收割」卡在结算区不动，110 下正常。
  - 用户要求：同一份 mod 要能在 default 107 与 beta 110 两个版本都正常结算。
- **实装更改概括**：
  - 修复 107 结算中断：按游戏版本为 `AttackCommand.FromCard` 选择对应重载。
  - 构建流程增加版本判定：`build.ps1` 按 `release_info.json` 的版本设置 `STS2_GE_110` 编译常量。
  - `<0.110` 与 `≥0.110` 两套 `FromCard` 调用逻辑，条件编译二选一。
- **简略技术细节**：
  - 根因：110 才有 `AttackCommand.FromCard(CardModel, CardPlay?)`；107 只有 `FromCard(CardModel)`，按 110 编译的 DLL 在 107 首次调用即抛 `MissingMethodException`。
  - 构建：`dotnet build -c Debug` 前读取游戏 `release_info.json` 判定 minor 版本，写 `DefineConstants`。
  - 代价：一个版本的游戏需要一次对应构建，产物不可互换。
- **失败经验或实验教训**：
  - 编译期版本探测把「版本适配」绑定到构建机，切版本必须重新构建，改一处就要重编两份，容易发错包。
  - **清单原件未保留**：本地打包目录 `ReaperReplacementMod v2（修改本地化键…）` 的清单版本为 `0.2.0`，`ReaperReplacementMod v3（…同时兼容两个版本…）` 已是 `1.0`，因此 0.2.1／0.2.2 的清单版本号只有 ADR-001 的文字记录，打包件对应关系未记录。
- **提交编号**：无（GitHub 仓库 2026-08-09 才建立，此前无提交历史）

## 版本 0.2.2（2026-08-08）

- **版本号**：0.2.2
- **时间戳**：2026-08-08（ADR-001「再调整（v0.2.2）」条目）
- **开发人员反馈**：
  - 对 0.2.1 的「每个游戏版本各编一份」不满意，要求单一 DLL 双版本通用、免重新构建。
  - 状态：已构建安装，待用户实机验证（ADR-001 状态行）。
- **实装更改概括**：
  - 撤销条件编译与版本探测，改为运行时反射分派 `FromCard` 重载。
  - 单一 DLL 同时适配 107/110，切版本不再需要重新构建。
- **简略技术细节**：
  - `NotYetOnPlayPatch` 静态字段缓存 `AttackCommand.FromCard(CardModel, CardPlay)` 与 `FromCard(CardModel)` 两个 `MethodInfo?`。
  - 执行时「双参重载存在则用双参，否则用单参」，`Invoke` 后强转回 `AttackCommand` 继续链式构建器。
  - 其余构建器方法（`TargetingAllOpponents` / `WithHitFx` / `Execute`）两版签名一致，只需分派一处。
- **失败经验或实验教训**：
  - 反射分派把「找不到任何重载」的风险留在了运行期（单参重载用 `!` 非空断言），若未来版本移除单参重载会抛 `NullReferenceException`，源码无兜底。
  - 本次改为运行时判定后，`build.ps1` 里的版本探测逻辑被移除，构建不再依赖 `release_info.json`。
- **提交编号**：无（同上，早于仓库建立）
