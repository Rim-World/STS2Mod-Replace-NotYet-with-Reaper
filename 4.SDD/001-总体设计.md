# 总体设计：死亡收割（ReaperReplacementMod）

- 版本：1.0（`9.SRC/ReaperReplacementMod/ReaperReplacementMod.json` 的 `version`；游戏 `mods/ReaperReplacementMod/` 内清单一致）
- 面向游戏版本：`min_game_version = 0.107.1`；设计目标为 `0.107.x` 与 `0.110.x` 共用同一份 DLL
- 信息出处：`9.SRC/ReaperReplacementMod/` 源码与工程文件、`1.ADR/001-时候未到整卡替换为死亡收割.md`、`2.PLANS/001-G-时候未到整卡替换为死亡收割.md`、`3.DOCS/` 两篇文档、mod 清单
- 未在源码/文档中出现的内容一律标注「未记录」

## 1. 设计目标

把塔2 铁甲战士技能牌「时候未到」（`NotYet`）整卡替换为塔1 铁甲战士攻击牌「死亡收割」（`Reaper`），替换范围包括卡名、卡面文本、卡图、卡牌类型、目标、数值与打出效果。约束：

- **直接在原卡上改**：不生成新卡牌、不禁用原卡，避免改动卡池与存档中的卡牌引用（ADR-001）。
- **最小依赖**：`dependencies: []`；`0Harmony` 与 `sts2` 仅作编译期引用（`Private=false`），不随包分发。
- **单一 DLL 跨版本**：107 与 110 的 API 差异在运行时判定，不依赖编译期宏、不需要为每个游戏版本各构建一次。
- **资源自足**：卡图与 15 语言文本随 pck 分发，另有 DLL 内嵌 PNG 兜底。
- **不改动的部分**：费用（2）、稀有度（Rare）、`Exhaust` 关键词、`CanBeGeneratedInCombat = false`（`NotYet` 自身取值，未打补丁）。

## 2. 模块划分与职责

| 模块 | 文件 | 职责 |
|---|---|---|
| 入口 | `ModEntry.cs` | `[ModInitializer("ModLoaded")]` 标注的静态入口；常量 `ModId = "ReaperReplacementMod"`、`PortraitPng = "res://ReaperReplacementMod/images/card_portraits/big/reaper.png"`；`ModLoaded()` 内 `new Harmony(ModId)` 后 `PatchAll(Assembly.GetExecutingAssembly())`，整体 try/catch，失败记 `Log.Error` |
| 总开关 | `ModConfig.cs` | `IsReplaceNotYetEnabled => true`，固定开启；注释说明「已移除 RitsuLib 实时开关，避免会话中途切换导致 DynamicVars／卡面状态不一致」。所有补丁都以此开关做守卫 |
| 核心属性补丁 | `Patches/NotYetCorePatches.cs` | 三个类：`NotYetTypePatch`（`CardModel.Type` getter Postfix → `CardType.Attack`）、`NotYetTargetTypePatch`（`CardModel.TargetType` getter Postfix → `TargetType.AllEnemies`）、`NotYetCanonicalVarsPatch`（`NotYet.CanonicalVars` getter Postfix → `new[] { new DamageVar(4m, ValueProp.Move) }`） |
| 打出/升级补丁 | `Patches/NotYetOnPlayPatch.cs` | `NotYetOnPlayPatch`：`NotYet.OnPlay` 的 Prefix，短路原实现并执行 AOE 伤害＋吸血；`NotYetOnUpgradePatch`：`NotYet.OnUpgrade` 的 Prefix，改用 `DynamicVars.Damage.UpgradeValueBy(1m)`（4→5）后短路 |
| 卡图补丁 | `Patches/NotYetPortraitPatches.cs` | 三个 Prefix：`CardModel.PortraitPngPath` / `CardModel.PortraitPath` 直接返回 `ModEntry.PortraitPng`；`CardModel.Portrait` 返回 `PortraitTextureLoader.Get()` |
| 文本补丁 | `Patches/NotYetTextPatches.cs` | `CardModel.TitleLocString` / `CardModel.Description` getter Postfix，换成 `LocString("cards", "RE_REAPER.title" / "RE_REAPER.description")` |
| 卡图加载 | `PortraitTextureLoader.cs` | 静态缓存纹理；先 `ResourceLoader.Load<Texture2D>("res://…big/reaper.png")`，失败则从程序集内嵌资源 `ReaperReplacementMod.assets.reaper_big.png` 解码成 `ImageTexture` |
| 资源包内容 | `ReaperReplacementMod/`（Godot 资源目录） | `mod_image.png`、`images/card_portraits/reaper.png`（250×190）、`images/card_portraits/big/reaper.png`（1000×760）、`localization/<15 语言>/cards.json`；`export_presets.cfg` 以显式清单（`export_filter="resources"` + `export_files`）决定进包内容 |
| 内嵌兜底资源 | `assets/reaper_big.png` | 由 `ReaperReplacementMod.csproj` 的 `EmbeddedResource` 以 `LogicalName=ReaperReplacementMod.assets.reaper_big.png` 嵌入 DLL |
| 清单 | `ReaperReplacementMod.json` | `id=ReaperReplacementMod`、`name=死亡收割 (Reaper)`、`version=1.0`、`has_dll/has_pck=true`、`min_game_version=0.107.1`、`dependencies=[]`、`affects_gameplay=true` |
| 构建 | `build.ps1` | `dotnet build -c Debug` → Godot `--headless --import` → `--headless --export-pack "Windows Desktop"` → 拷贝 dll/pdb/json 到 `C:\Game\Steam\steamapps\common\Slay the Spire 2\mods\ReaperReplacementMod\` |
| 工程 | `ReaperReplacementMod.csproj`、`project.godot`、`export_presets.cfg` | `Godot.NET.Sdk/4.5.1`、`net9.0`、`AllowUnsafeBlocks`；引用游戏 `data_sts2_windows_x86_64/` 下的 `0Harmony.dll`、`sts2.dll`；导出预设 `binary_format/architecture="msil"` |

依赖方向单向：`ModEntry` → 各补丁类；补丁类 → `ModConfig`（开关）、`ModEntry`（卡图路径常量）、`PortraitTextureLoader`（纹理）。补丁类之间互不引用。

## 3. 补丁策略

### 3.1 核心属性（迭代式 Postfix）

```
Type           Postfix: __instance is NotYet && 开关 → CardType.Attack
TargetType     Postfix: __instance is NotYet && 开关 → TargetType.AllEnemies
CanonicalVars  Postfix: 开关 → 仅返回 DamageVar(4m, ValueProp.Move)
```

`CanonicalVars` 直接补 `NotYet.CanonicalVars`（该方法本身就是 `NotYet` 的 override），而不是补基类，避免影响其它卡。原卡的治疗变量 `HealVar(10)` 因此被完全替换为伤害变量。

### 3.2 打出效果（Prefix 短路 + 自实现）

```
Prefix(PlayerChoiceContext choiceContext, CardPlay cardPlay, NotYet __instance, ref Task __result)
  if (!开关) return true;                         // 放行原版：治疗 10(13)
  __result = ReaperOnPlay(...); return false;     // 短路

ReaperOnPlay:
  AttackCommand cmd = DamageCmd.Attack(__instance.DynamicVars.Damage.BaseValue)
  cmd = 反射分派 FromCard(card, cardPlay) 或 FromCard(card)
  attack = await cmd.TargetingAllOpponents(__instance.CombatState)
                     .WithHitFx("vfx/vfx_giant_horizontal_slash")
                     .Execute(choiceContext)
  heal = 所有结果摊平后 Sum(UnblockedDamage)
  if (heal > 0) await CreatureCmd.Heal(__instance.Owner.Creature, heal)
```

吸血口径采用 `Results` 中的 `UnblockedDamage`（实际扣血，不含溢出），与 STS1 死亡收割一致；`heal > 0` 才调用治疗命令，避免 0 治疗产生多余表现。

### 3.3 升级效果（Prefix 短路）

```
Prefix(NotYet __instance)
  if (!开关) return true;                         // 放行原版：Heal +3（10→13）
  __instance.DynamicVars.Damage.UpgradeValueBy(1m);  // 4 → 5
  return false;
```

> 数值说明：升级伤害以源码为准，为 `UpgradeValueBy(1m)`（4→5）。ADR-001 与翻译审批文档原记「升级 +2（4→6）」，已于 2026-11-01 按用户拍板修正为 +1。

### 3.4 卡图（三来源统一 Prefix）

`CardModel.PortraitPngPath`、`CardModel.PortraitPath`、`CardModel.Portrait` 三个 getter 全部命中 `NotYet` 实例时：

- `PortraitPath` / `PortraitPngPath` → 返回 pck 内 `res://ReaperReplacementMod/images/card_portraits/big/reaper.png`；
- `Portrait` → 返回 `PortraitTextureLoader.Get()` 加载的纹理。

三处同时替换，保证图鉴、卡牌、卡面大图等不同渲染路径拿到同一张 STS1 卡图。

### 3.5 文本（切键，不覆写官方键）

`TitleLocString` / `Description` 的 Postfix 返回 `new LocString("cards", "RE_REAPER.title" / "RE_REAPER.description")`。新增模组专属前缀 `RE_REAPER.*` 而不是覆写官方 `NOT_YET.*`，避免与其它改写官方键的 mod 发生 patch 顺序竞争；关闭开关时（当前恒为开）可直接回退原版键。

## 4. 数据流

```
玩家打出「死亡收割」（实际仍是 NotYet 实例）
   → CardModel.Type / TargetType / CanonicalVars 补丁已把卡面显示为 攻击/全体/4 伤
   → NotYet.OnPlay Prefix 命中 → ReaperOnPlay
        → DamageCmd.Attack(4) → 目标全体敌人 → Execute
        → 汇总各目标 UnblockedDamage → CreatureCmd.Heal
   → 升级时 NotYet.OnUpgrade Prefix 命中 → Damage.UpgradeValueBy(1)（4→5）
   → 渲染：TitleLocString/Description → RE_REAPER.*；Portrait 系列 → STS1 卡图
```

存档层面：由于是同一张卡换皮，历史记录里的 `CARD.NOT_YET` 在 mod 开启时显示为死亡收割，关闭后恢复原状（`description/死割_中文.md` 的表述）；mod 不新增持久化字段。

## 5. 107/110 兼容设计

- 事实：`AttackCommand.FromCard(CardModel, CardPlay)` 只在 ≥0.110 存在；107 只有 `FromCard(CardModel)`。按 110 编译的 DLL 在 107 首次调用会抛 `MissingMethodException`（ADR-001〔原 ADR-005〕记录的现场结论：107 下打出死亡收割卡在结算区）。
- v0.2.1 方案：建构建期条件编译（`build.ps1` 依 `release_info.json` 设置 `STS2_GE_110`），两套逻辑各编一次。
- v0.2.2 起的现行方案：`NotYetOnPlayPatch` 静态字段缓存两个 `MethodInfo?`（双参重载、单参重载），运行时判断「双参存在则用双参，否则用单参」，`Invoke` 后强转 `AttackCommand`。撤销条件编译与版本探测，**单一 DLL 双版本通用，切版本无需重新构建**。
- 其余构建器方法（`TargetingAllOpponents`、`WithHitFx`、`Execute`）两版签名一致，因此只需分派 `FromCard` 一处。

## 6. 资源与本地化

- 15 个语言目录：`deu / eng / esp / fra / ita / jpn / kor / pol / ptb / rus / spa / tha / tur / zhs / zht`，每个 `cards.json` 只含两个键：`RE_REAPER.title`、`RE_REAPER.description`。
- 文本来源：STS1 本地正版 `desktop-1.0.jar` 的 `localization/<lang>/cards.json` 中 `Reaper` 条目，经统一规则转换：`!D!` → `{Damage:diff()}`、删除尾部「消耗」句（塔2 用关键词徽记渲染）、`NL` → 空格、按语言清理标点与多余空格；逐语言对照见 `3.DOCS/002-T-死亡收割卡面文本翻译审批.md`。
- 卡图：`images/card_portraits/big/reaper.png`（1000×760）与 `images/card_portraits/reaper.png`（250×190）来自 STS1 素材；`assets/reaper_big.png` 为同图的 DLL 内嵌兜底副本。
- 模组图标：`mod_image.png`，ADR-001 记录为「420×420 纯色占位（待用户替换）」。

## 7. 异常处理与降级

| 场景 | 处理 |
|---|---|
| `PatchAll` 抛异常（Harmony 版本/目标签名不符等） | `ModLoaded` 整体 try/catch，`Log.Error` 记录；不向游戏抛出 |
| pck 内卡图加载失败（`ResourceLoader.Load` 返回空或抛异常） | `Log.Warn` 后回退 DLL 内嵌 PNG；内嵌解码再失败则 `Log.Error` 并返回空纹理 |
| 反射未找到任何 `FromCard` 重载 | 代码直接使用 `FromCardOneArg!`（非空断言）；此路径的保护为「假定 107 一定存在单参重载」，源码无兜底分支 |
| 全体攻击未造成实际扣血（全部被格挡/溢出） | `heal <= 0` 时不调用 `CreatureCmd.Heal` |
| 目标不是 `NotYet` 实例或开关关闭 | 所有补丁直接 `return true` 放行原版实现 |

## 8. 构建与测试

- 构建：`9.SRC/ReaperReplacementMod/build.ps1`，依赖 `dotnet`（net9.0）与 Godot 4.5.1 mono（路径硬编码 `C:\Godot&GDRE\…`）；产物 dll/pdb/pck/json 直接落到游戏 `mods/ReaperReplacementMod/`。
- 验证方式（按 ADR/计划记载）：静态验证（DLL 元数据、补丁类存在性、pck 内本地化与卡图、清单 schema）已通过；**游戏内实机验证结论未记录**（开/关、有无 RitsuLib 两种组合均未记录结论）。
- 版本号一致性：清单 `version` 与发布包名、Release 标签 `v1.0` 一致；整理前后未改版本号。

## 9. 已知限制与待办

1. 升级数值：已统一为 +1（4→5）；ADR-001、计划与翻译审批文档已同步（2026-11-01）。
2. 实机验证结论缺失：107 与 110 两个版本、有无 RitsuLib 的组合都没有留下验证记录。
3. `DynamicVars` 缓存：计划文档记录的风险——运行中切换开关时，已实例化卡牌的变量/文本可能延迟到下次实例化才生效；当前 `ModConfig` 固定开启，该风险实际不触发。
4. `FromCard` 反射兜底：若未来版本连单参重载也移除，`FromCardOneArg!` 会抛 `NullReferenceException`（被 Harmony 调用链抛出，源码无保护）。
5. RitsuLib 设置页与互操作状态文件（ADR-001 记载的 `ritsu_interop_state.json`）在当前源码中已不存在，文档保留为历史记录；移除原因见 `ModConfig.cs` 注释（避免会话中途切换导致状态不一致）。
6. 卡面大图与图标规格的来源尺寸未在源码中记录（`pics/素材图/sts1_reaper.png` 500×380、`sts2_not_yet.png` 1000×760 见 ADR-001）。
